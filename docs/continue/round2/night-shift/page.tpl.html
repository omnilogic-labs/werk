werk

Work carries on after you close the lid.

werk starts a process somewhere and lets you come back to it later. On the Mac mini on your desk, on a machine you can ssh to, in a container it provisions, on the company cluster. Your repository lands there on a fresh branch, the terminal survives your laptop closing, and every one of those sessions — across every machine — is on one list.

● Working today — CLI, TUI, werk serve in your browser ○ Planned — hosted view, shared sessions, the company-wide view

The argument

There are two interfaces to a repository that everything already speaks: a terminal and git. People use them. So do the agents worth running, because those agents are command-line programs. werk makes both trivial to reach, from anywhere, on any machine you have.

Claude Code, Codex, Gemini CLI, Aider — werk dispatches and monitors them with no per-agent integration and no plugin for each one. An agent released next month works on the day you install it.

02:14Working today

Nobody is watching it, and it does not need watching.

The session stays a terminal, not a log file. Full-screen TUI, colours, the agent redrawing its own progress bar, the prompt it puts up when it wants a decision. Hours of scrollback, kept.

werk does not need to understand the agent to know how it is doing. It reads what any well-behaved terminal program already emits, and has emitted for forty years:

signals werk listens for 
BEL           the bell — it wants you
OSC 9 / 777   a notification, with text
OSC 9;4       progress, 0–100, and stalled
OSC 133       where each command began, ended, exit status

No integration per agent. No plugin to keep current. If the tool is well behaved in a terminal, werk already knows what it is doing.

Three places you can be standing

  • Terminal

    Bare werk for the fleet. werk run to dispatch. werk attach to step inside one.

  • TUI

    Steer the whole fleet without leaving the terminal — every session, every host, one screen.

  • Browser

    werk serve runs locally and gives you the same thing as a web app: every session on every machine, and you can type into any of them.

Then: hand somebody the terminal itself.

You copy a link out of a session and put it in a message. They open it and they are in your terminal — the live one, the same session, not a recording and not a screenshot pasted into a thread.

The eight hours of scrollback come with it, so they catch up by reading rather than by you narrating. They can watch. If you let them, they can type, and then there are two of you in one terminal, on a machine that belongs to neither of you.

One link per session, scoped to that session, revoked when you are done with it. This is the shape it is being designed to.
