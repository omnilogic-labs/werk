werk.

Field manual for dispatching work to machines you are not sitting at

werk starts a process somewhere and lets you come back to it later.

Section 0

NoteOne binary. No runtime on the far machine, no package manager, no git at the other end. werk copies itself over the ssh connection it already has.

General description

What you are holding

You are running a lot of long-lived, half-autonomous processes. Mostly coding agents. Each one wants a terminal, wants an hour or four, wants its own copy of the repository on its own branch, and every so often wants you.

Today the terminal comes from tmux, the branch from git worktree, and the machine from ssh and hope. None of the three knows the other two exist, and none of them knows there are eleven of these running.

werk is the one tool for all of it. It finds somewhere for the work to happen — the mini on the desk, a VPS, a container it builds on the spot, the cluster you already run — puts your code there on a fresh branch, hands you a terminal that outlives your laptop, and then shows you every one of those, across every machine, in one list you can open from a terminal or a browser.

The two universal interfaces to a repository, for people and for agents alike, are the terminal and git. werk exists to make both trivially easy to reach from wherever you happen to be.

Serviceability

This manual covers three operations. One is in service now. Two are drawn and not yet built, and are marked as such wherever they appear.

Part One
In service

NoteBare werk is the most-typed command in the product. It prints and exits, like ls. Its latency budget is the tightest constraint in the design.

CautionA workspace destroyed with unpushed commits inside it is a catastrophic bug, not an edge case. werk rm refuses when work would be lost.

Operation one — single operator

Send it somewhere and walk away

The first time, you are on your own, and it takes one command.

werk create picks a placement, builds it if it is not there, seeds your repository onto a fresh branch and drops you into a terminal on the far side. The prompt you land on is not your laptop's.

Local terminal — your laptop1 of 3 
$ werk create --on bigbox
  Created workspace 'affectionate-badgers-writing'
  · ssh:bigbox
  · branch werk/affectionate-badgers-writing off main
  · 1.2 GiB repository seeded in 3.4s
  · attaching…

Then you start the agent. werk has no opinion about which one: Claude Code, Codex, Gemini CLI, Aider. They are command-line programs, and holding command-line programs is the entire trick.

Inside the session — bigbox2 of 3 
badgers ~/repo $ claude
> pull the billing module apart so payments and invoices
  stop sharing state, then make the tests pass

  Reading src/billing/… (114 files)
  ^\ detached — session still running

Ctrl-\ and you are out. Not stopped, out. The agent carries on talking to a terminal that is still there; you are somewhere else.

Now shut the lid. Get on a train. The wifi drops, the router reboots, the laptop sleeps for four hours in a bag. None of that reaches the process, because none of it is where the process is.

Local terminal — back at your desk3 of 3 
$ werk attach affec
  … 4h 12m of scrollback, exactly as you left it
> tests pass. 41 files changed on werk/affectionate-badgers-writing.
  want me to open the PR?

Not a redraw. The real terminal state, colours, cursor position and scrollback, restored from a snapshot of what the screen actually was. Nothing about the last four hours is missing.

Then werk pull affec and the commits are in your local repository. werk made the branch, werk got the code out there, werk brings the work back. You never git remote add a container.

Or do all of that in a browser

werk serve runs on your own machine, aggregates every placement and serves one page: every session on every machine, live, as a grid of terminals you can type into. It is on your phone if your phone is on the same wifi. It is opt-in, loopback by default, and it prints a one-time token when it starts.

That is the product as it stands. Everything above this line works today.

Part Two
Planned

NoteRead-only viewing of your own sessions exists today: werk attach --read-only. What is missing is a link that reaches someone who is not you.

Operation two — two operators, one terminal

Hand someone the live one

Everything so far assumes one person's fleet. The next thing werk should do is let there be two of you in it.

A session has got somewhere interesting, or somewhere bad. You want a colleague in there — not a screenshot, not the last forty lines pasted into a channel, and not a recording. The live terminal, moving, with a cursor they can put their hands on.

Planned — not yet builtSharing 
$ werk share sleepy-otters --write
  https://werk.link/s/7Q2H-KDVN
  writable · expires in 2h · revoke with `werk unshare sleepy-otters`

You send the link. They open it and they are in, in a browser, on the same screen you are looking at, watching the same output arrive. Read-only unless you say otherwise, revoked the moment you are done, and gone on its own if you forget.

This is the point at which werk needs somewhere a link can point — a rendezvous both of you can reach, rather than a port on your laptop. That same piece is what puts the fleet on your phone from another continent, which is why the two are drawn together and built together.

Operation three — the organisation

Every session in the building

Once a session can be shared, the fleet stops belonging to one person.

The third operation is a single view of every agent session in the organisation. Each person, the sessions they have running, and the subagents those sessions have spawned — down as many levels as they go. Open any row and you are on its live terminal.

What that answers, and nothing currently answers: how much is actually running right now, which of it is stuck waiting on a human, where the compute went, and what the agent three levels down is doing in your repository.

And it answers it the same way as everything else in werk — by opening the terminal. Not a log shipped somewhere and parsed after the fact. The session, as it is this second, at whatever depth it sits.

Appendix

NoteMeaning is built on structured signals, never on scraping the rendered screen. Anything heuristic is labelled heuristic.

Reference

How it holds any agent

There is no per-agent integration and no plugin per vendor. werk reads the signals a well-behaved terminal program already emits, which means an agent released next month works on the day you install it, with no werk release in between.

Signal What werk takes from it
BEL The program rang. Oldest attention signal there is, and still the most common.
OSC 9 · OSC 777 A desktop notification with a body. This is how “needs you” usually arrives.
OSC 9;4 Progress state and percentage, for the ones that report it.
OSC 133 Command boundaries and exit status. Where one command ended and whether it worked.
OSC 7 The working directory, so werk knows where the session actually is.
Process exit It finished, and with what code.

The same floor means werk create --run 'npm run dev' is as good a citizen as werk create --run claude.

Where work can run

Placement What it is
local Your own disk, in the repository or a worktree of it.
ssh:<host> Any machine in your ssh config. werk puts itself there.
docker A container werk builds on your machine.
docker@host A container werk builds on someone else's.
k8s, cloud The cluster you already run, and provider sandboxes. Later.

Change the default in config and every subsequent werk create lands somewhere else, without changing a single habit. Start local, get serious, move it to a big box.

The commands you will actually type

Command Does
werk Print the fleet and exit.
werk create Provision, seed, branch, attach. Everything else is a flag on this.
werk attach <name> Get inside a session. --read-only to watch without the risk.
werk ui The fleet as a terminal UI, with live previews.
werk serve The fleet as a web page, on your own machine.
werk diff · pull What has this workspace done, and bring its branch home.
werk watch Block until something needs you. The scriptable notification.
werk ls --json Every read command has one. werk composes with what you already have.
Closing

What is being asked for

Part One is real and you can put an agent on another machine with it this afternoon.

It is also the hard part. A detachable terminal session that survives the laptop closing, the network dropping and the client dying — on a machine nobody is sitting at, with the repository on its own branch and the commits coming home — is most of the engineering, and it is done.

Parts Two and Three are the same piece of work twice: somewhere a link can point. Give a session a public address and a permission on it, and sharing is a link you send to one person and the company view is the same list with more than one name in it. The sessions, the fleet, the terminals and the machine-spanning are already built.

That address is what is being asked for. Everything on this page after it follows.
